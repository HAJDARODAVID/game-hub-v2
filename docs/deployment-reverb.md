# Deploying Reverb (real-time updates) on a LAMP server

> **Status:** Reverb is **installed and used** for real-time updates (rooms, moves, invites, lobby, footer).
> Events are sent immediately (`ShouldBroadcastNow`), so **no queue worker is needed for real-time**.
> If Reverb is down the game still works: changes are saved, a warning is logged, and pages catch up through slow fallback polling (30–60 s).

## What Reverb is and why it needs extra setup

Reverb is Laravel's WebSocket server. It pushes updates (player joined, invite received, move made) to browsers straight away, so pages don't have to poll.

A normal Laravel app is just PHP files that Apache runs on each request. Reverb is different: it's a **long-running PHP process** that keeps connections open all the time. Production therefore needs:

1. **Supervisor**, to keep Reverb running and restart it after a crash or reboot.
2. **An Apache reverse proxy**, so browsers reach Reverb through your normal HTTPS domain.
3. *(Optional)* **A queue worker**. Game Hub broadcasts immediately, so this is only needed if queued jobs/events are added later. The Supervisor example below includes one; leave the `gamehub-queue` block out if you don't need it.

```
Browser ──wss://gamehub.example.com/app/...──▶ Apache :443 ──proxy──▶ Reverb 127.0.0.1:8080
Laravel ──https://gamehub.example.com/apps/...─▶ Apache :443 ──proxy──▶ Reverb (to send events)
Queue worker ──runs broadcast jobs──▶ Reverb
```

**Requirement:** root/SSH access (a VPS or your own server). Shared hosting usually doesn't allow long-running processes; there, keep polling or use a hosted service such as Pusher.

The examples assume **Ubuntu/Debian**, the app in **`/var/www/game-hub-v2`**, Apache running as **`www-data`**, and the domain **`gamehub.example.com`**. Adjust these to match your server.

---

## 1. Supervisor

```bash
sudo apt install supervisor
```

Create `/etc/supervisor/conf.d/gamehub.conf`:

```ini
[program:gamehub-reverb]
command=php /var/www/game-hub-v2/artisan reverb:start --host=127.0.0.1 --port=8080
user=www-data
autostart=true
autorestart=true
minfds=10000                 ; allow many open connections
stdout_logfile=/var/www/game-hub-v2/storage/logs/reverb.log
redirect_stderr=true

[program:gamehub-queue]
command=php /var/www/game-hub-v2/artisan queue:work --sleep=1 --tries=3 --max-time=3600
user=www-data
autostart=true
autorestart=true
stdout_logfile=/var/www/game-hub-v2/storage/logs/queue.log
redirect_stderr=true
```

Load it:

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl status        # both should say RUNNING
```

## 2. Apache reverse proxy

Enable the proxy modules:

```bash
sudo a2enmod proxy proxy_http proxy_wstunnel
sudo systemctl restart apache2
```

Add this to the site's **HTTPS** virtual host, inside `<VirtualHost *:443>`:

```apache
ProxyPreserveHost On

# Laravel → Reverb (sending events). Must come before /app/
ProxyPass        /apps/ http://127.0.0.1:8080/apps/
ProxyPassReverse /apps/ http://127.0.0.1:8080/apps/

# Browsers → Reverb (WebSocket connections)
ProxyPass        /app/  ws://127.0.0.1:8080/app/
ProxyPassReverse /app/  ws://127.0.0.1:8080/app/
```

Check the config and reload Apache:

```bash
sudo apache2ctl configtest && sudo systemctl reload apache2
```

Port **8080 stays internal**. Don't open it in the firewall: all traffic goes through Apache on 443, using the existing SSL certificate.

## 3. Production `.env`

```env
BROADCAST_CONNECTION=reverb
QUEUE_CONNECTION=database

REVERB_APP_ID=...            # generated by php artisan install:broadcasting
REVERB_APP_KEY=...
REVERB_APP_SECRET=...

# Where Reverb itself listens (internal)
REVERB_SERVER_HOST=127.0.0.1
REVERB_SERVER_PORT=8080

# How browsers and Laravel reach it (public, through Apache)
REVERB_HOST=gamehub.example.com
REVERB_PORT=443
REVERB_SCHEME=https

# Read by the JavaScript build
VITE_REVERB_APP_KEY="${REVERB_APP_KEY}"
VITE_REVERB_HOST="${REVERB_HOST}"
VITE_REVERB_PORT="${REVERB_PORT}"
VITE_REVERB_SCHEME="${REVERB_SCHEME}"
```

The `VITE_*` values are compiled into the JavaScript, so run `npm run build` **after** changing them.

## 4. On every deploy

```bash
php artisan migrate --force
npm run build
php artisan config:cache
php artisan reverb:restart     # reload Reverb with the new code/config
php artisan queue:restart      # same for the queue worker
```

Long-running processes keep the old code in memory until they restart. Skipping the restart is the most common cause of "my change isn't showing".

## 5. Troubleshooting

| Symptom | Check |
|---|---|
| Nothing real-time works | `sudo supervisorctl status`: is `gamehub-reverb` `RUNNING`? |
| Browser can't connect | DevTools → Network → **WS**: expect `wss://gamehub.example.com/app/...` with status **101**. A 404/502 means the Apache proxy rules or the proxy modules are missing. |
| Connected, but no updates arrive | Look for `Real-time update not sent (is Reverb running?)` in `storage/logs/laravel.log`: Laravel can't reach Reverb through `/apps/`. Check the `/apps/` proxy rule and the `REVERB_HOST/PORT/SCHEME` values. |
| Channel subscription fails (403 on `/broadcasting/auth`) | The user may not view that room (see `routes/channels.php` / `RoomPolicy`), or their session expired. |
| Errors from Reverb itself | `tail -f storage/logs/reverb.log` |
| Change not showing after deploy | Run `php artisan reverb:restart` and `php artisan queue:restart`. |

## Local development

None of the above is needed locally. WAMP serves the site; run Reverb next to it in a terminal:

```bash
php artisan reverb:start --debug     # leave running while you develop (Ctrl+C to stop)
npm run dev                          # or `npm run build` after JS/SCSS changes
```

Locally `.env` uses `REVERB_HOST=localhost`, `REVERB_PORT=8080` and `REVERB_SCHEME=http`.
On the WAMP setup, run `php artisan config:cache` after any `.env` change, and `npm run build` after changing `VITE_REVERB_*` values.
